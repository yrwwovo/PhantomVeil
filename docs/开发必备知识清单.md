# security-agent-lab 开发必备知识清单

这份清单按项目实际进度安排学习顺序。目标不是先学完整套理论，而是确保你能解释当前代码、亲自运行演示、看懂测试结果，并知道下一步为什么这样设计。

## 当前项目能做什么

- 使用 Scope Guard 离线检查 URL 的协议、主机、端口和路径。
- 对明确授权的目标执行一次受限 HTTP GET。
- 解析并固定获准的连接 IP，阻止域名解析到未授权地址。
- 限制超时、响应大小和重定向次数。
- 每次重定向重新检查授权范围。
- 使用本地测试服务器验证行为，不依赖公网网站。
- 把校验通过的证据整理为引用 Evidence ID 的中文 Markdown 观察报告。
- 已有一个仅接收 URL 的 OpenCode 自定义工具适配层；本地链路测试通过，实际 OpenCode 加载仍待验证。

当前还不是完整的渗透测试 Agent：OpenCode 工具文件已经建立，但尚未在用户的实际 OpenCode 安装中完成加载验证；同时还没有漏洞假设、漏洞验证或身份测试。现有报告只整理 HTTP 观察，不判断漏洞。

## 现在必须掌握

### 1 项目安全边界

- 只测试自建靶场、CTF 或明确授权目标。
- 默认拒绝：没有写进允许范围的目标不执行。
- 当前只允许 GET，不使用 Cookie、密码或破坏性操作。
- 工具执行成功只代表拿到了响应，不代表发现了漏洞。

检查自己：能说明为什么公网随机网站不能直接加入测试目标。

### 2 URL 的组成

示例：`http://127.0.0.1:5000/api/users?id=1`

- `http`：协议 scheme。
- `127.0.0.1`：主机 host。
- `5000`：端口 port。
- `/api/users`：路径 path。
- `id=1`：查询参数 query。

检查自己：能指出 Scope Guard 当前检查哪些部分，以及暂未对查询参数设置细粒度规则。

### 3 Scope Guard 的范围规则

- `allowed_hosts` 精确列出授权主机。
- `allowed_ports` 列出授权服务端口。
- `allowed_paths: ["/"]` 允许该主机全部路径。
- `allowed_paths: ["/api"]` 允许 `/api` 及其子路径，但不允许 `/apiv2`。
- `denied_paths` 优先于 `allowed_paths`。

阅读：`configs/scope.example.json`、`src/scope/scope-guard.ts`。

### 4 JSON 配置

- `{}` 表示对象，`[]` 表示数组。
- 字符串使用双引号。
- 数字不加引号。
- JSON 不支持注释和末尾多余逗号。

检查自己：能修改允许端口并通过 `npm run scope:demo -- URL` 观察结果。

### 5 Node.js 与 npm scripts

- Node.js 负责运行 TypeScript/JavaScript 文件。
- `package.json` 的 `scripts` 是命令快捷方式表。
- `npm test` 等价于运行其中的 `test` 命令。
- `node --test tests/*.test.ts` 会加载所有 `.test.ts` 测试文件。

检查自己：能解释 `npm run http:demo` 最终执行哪个文件。

### 6 TypeScript 最小基础

- `const` 和 `let`：保存值。
- 对象和数组：组织配置和结果。
- `function`：封装可重复逻辑。
- `interface`：描述对象应有哪些字段。
- `import` 和 `export`：在文件之间使用函数与类型。
- `if`、`return`、`try/catch`：判断、返回和错误处理。

当前不需要学习复杂泛型、装饰器或前端框架。

### 7 异步与 Promise

- 文件读取、DNS 和 HTTP 请求需要等待结果。
- `async` 表示函数会异步完成。
- `await` 等待 Promise 成功或失败。
- 超时用于防止请求一直占用程序。

阅读：`scripts/http-get-demo.ts`，先观察 `await restrictedHttpGet(...)`。

### 8 HTTP GET 基础

- GET 用于读取资源。
- 状态码表示结果，例如 200、301、404、500。
- 响应头描述内容类型、长度和缓存等信息。
- 响应正文是页面或接口返回的数据。
- 301、302、307、308 等状态可能要求访问新地址。

检查自己：能在 `npm run http:demo` 输出中找到状态码、响应头、正文和字节数。

### 9 DNS IP 固定与 SSRF

- 域名需要先解析为 IP 才能连接。
- 仅允许域名仍可能连接到非预期内网 IP。
- `allowed_resolved_ips` 明确限制实际连接地址。
- 选定地址后固定本次连接使用该 IP，减少解析结果变化造成的绕过。
- 每一个重定向目标都要重新检查。

阅读：`configs/http.example.json`、`capabilities/web/restricted-http-get.ts`。

### 10 结构化结果

- `ok` 或 `allowed` 表示是否成功。
- `code` 是稳定的机器可读结果，例如 `IP_NOT_ALLOWED`。
- `reason` 是给人看的中文说明。
- Agent 后续应读取结构化字段，不能根据一段自然语言自行猜测执行是否成功。

### 11 自动测试

- Arrange：准备配置和本地服务器。
- Act：调用待测试函数。
- Assert：比较实际结果与预期结果。
- 一个断言失败时，Node 测试运行器把该项标记为失败并返回非零退出码。
- HTTP 测试只连接临时的 `127.0.0.1` 服务。

阅读顺序：先看 `tests/scope-guard.test.ts`，再看 `tests/restricted-http-get.test.ts`。

### 12 证据与哈希

- 观察 observation 是工具实际返回的数据。
- 结论 conclusion 是根据观察作出的判断，两者必须分开。
- 证据编号用于让报告准确引用原始观察。
- SHA-256 哈希用于检查保存后的证据内容是否发生变化。
- 脱敏用于避免把令牌、Cookie 或密码写入可读记录。
- 哈希能发现修改，但不能证明证据最初一定真实。

### 13 Git 最小知识

- `git status` 查看哪些文件发生变化。
- `git diff` 查看已跟踪文件的具体变化。
- `git add` 选择要纳入版本的文件。
- `git commit` 保存一个可回退的开发节点。
- `.gitignore` 防止证据、报告和秘密被提交。
- `configs/*.local.json` 保存实际授权目标并被 Git 忽略；`*.example.json` 只展示格式。

当前仓库尚未创建首次提交。首次提交前应检查所有待提交文件，不提交 `evidence/` 中的运行产物。

## 接入 OpenCode 前需要掌握

- Agent 与工具的区别：Agent 负责选择下一步，工具负责确定性执行。
- 工具输入输出契约：字段、类型、错误码和限制必须明确。
- 权限不能由模型自行授予，Scope Guard 位于执行层。
- 网页和工具输出属于不可信数据，不能把其中的文字当作系统指令。
- 证据不足时返回待验证，不能强行生成漏洞结论。
- 人工确认点应放在高影响验证动作之前。

## 后期再学习

- 漏洞假设状态机：待验证、验证中、已确认、已排除、证据不足。
- 身份与权限对照测试。
- 可重复基准、误报率、人工介入次数和模型成本。
- 检索增强、长期记忆和上下文压缩。
- 共享黑板、任务调度、租约、去重和多 Agent 协作。
- 网络扫描、提权与横向移动不属于当前阶段。
