# 本机开放重定向观察原型

## 本阶段要回答的问题

在明确授权的本机靶场上，Agent 选中页面中已有的 GET 跳转参数后，项目能否以有限请求取得可复核的服务端跳转证据，并把正文回显、站内跳转、固定外站跳转排除在候选之外。

## 已实现的边界

- 输入为已校验的 HTML EV、静态 GET 表单序号、表单中的跳转参数名和本地授权引用。当前只接受本机靶场地址、同源表单、无现有查询参数的 action 和有限的跳转参数名。
- `redirect_probe` 是单独的授权动作；OpenCode 工具调用前还要取得一次人工审批，覆盖两次请求。旧授权记录不自动获得这个动作。
- 每次请求使用不同的 `https://phantomveil-probe.invalid/…` 标记。HTTP 客户端只读取第一个响应，绝不访问 `Location` 指向的地址。两次请求分别进入 Scope Guard、IP 策略及会话请求预算。
- 两个 3xx `Location` 都精确等于各自标记且跨源，才输出 `candidate`。这是待人工复核的观察，不是漏洞确认。两个响应及报告保存在本机的忽略目录中。

## 本地已知答案样本

自动测试在本机 HTTP 服务上覆盖：两个不同标记均被跳转、站内跳转、正文回显、固定外站跳转、无授权、敏感表单、请求预算只剩一次、非本机目标、来源 EV 被篡改、缺少或拒绝人工审批，以及观察首个重定向时不访问目的地。测试只验证工具和判断规则，不代表模型已经自主选对参数，也不代表真实站点发现率。

运行局部验证：

```powershell
node --test tests/authorized-redirect-probe.test.ts tests/restricted-http-get.test.ts tests/target-setup.test.ts
```

## 2026-10-02 真实模型与固定规则接线评测

本轮得到用户在聊天中对本机评测的明确批准。运行器只在仓库外的 Agent 隔离副本，把 `redirect_probe` 的 `ask` 改成针对本轮任务的预批准 `allow`；源码仓库中的日常人工审批保持 `ask`，OpenCode 没有使用 `--auto`。批准记录由运行器保存，不能单靠 `result.json` 证明聊天中的原始批准，应与本次对话一起审计。每一方各有 3 次 GET 上限：页面一次、两个标记请求。靶站只监听 `127.0.0.1`，禁止 `/blocked`。

```powershell
node benchmarks/redirect-probe/run.mjs --model=deepseek/deepseek-flash --case=external --approved-local-task
```

`--case` 还接受 `internal`、`body`、`static`。`--approved-local-task` 仅在用户明确批准这项本机主动评测后使用。运行结果及原始模型事件默认保存在本地用户数据目录的 `PhantomVeil/redirect-eval-runs/<run-id>/`，也可用 `PVEIL_EVAL_RUNS_DIR` 指向仓库外目录。这些目录含完整请求和 EV，不提交。

固定规则读取同一首页，用现有观察、表单清点和重定向检查函数选择第一个 `next` GET 表单；它不读取隐藏答案。独立评分器核对靶站实际请求、响应状态与 `Location`、三份 EV、报告、预算、最终结论及批准记录。评分器自测要求缺批准、额外请求、伪造响应、错误结论和污染报告均失败。

这四个单次样本只验证了接线和观察边界。固定规则也 4/4，耗时与 Token 成本更低；目前没有测出 Agent 的效果优势。负样本每类只跑一次，尚不能作为“零误报”的稳定性结论。下一步应固定评分器版本、让更多入口与线索变化，再按每个负场景至少 10 次运行统计误报；出现误报先归因。只有在同信息、同预算对照中出现可重复收益，才考虑扩大能力或 Agent 架构。
