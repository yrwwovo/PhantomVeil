# 真实 OpenCode 单 Agent：首个观察任务

运行：

~~~powershell
npm run agent:eval -- deepseek/deepseek-flash
~~~

模型名必须显式指定，且该模型需要已在 OpenCode 中可用。上面的模型只表示本次开发中成功运行过的配置；使用其他模型应单独记录，不混合统计。

脚本在本机 `127.0.0.1` 启动一个只读页面，为每次运行复制项目代码到独立工作目录，生成只允许该临时端口的 Scope 和 HTTP 策略，再通过 `opencode run --agent Phant0mV3il --format json` 启动**真实模型**。不使用 `--auto`，不读取或覆盖项目现有的本地授权配置。首次任务只要求观察页面并给出 HTTP 状态码；它不是漏洞扫描题。

原始 OpenCode 事件和运行工作目录默认保留在用户本地数据目录的 `PhantomVeil/agent-eval-runs/<run-id>/`（Windows 是 `%LOCALAPPDATA%` 下）；可用 `PVEIL_EVAL_RUNS_DIR` 改位置。工作目录必须在项目源码仓库外，以免 OpenCode 沿父目录加载主项目配置。运行目录可能含敏感内容，不要提交。`result.json` 记录任务、模型、源码摘要、提示词摘要、工具事件摘要、Token（如 OpenCode 提供）、耗时、靶站实际请求和评分结果。无 Git 提交的当前项目用复制后的源码 SHA-256 标识版本。

评分由 Agent 外的代码完成：必须恰好一次授权工具成功调用、靶站恰好收到一次预期 GET、工具给出本次目录内且 SHA-256 校验通过的 EV、EV 状态码符合事先答案、Agent 最终回答包含正确状态码。仅凭模型自称成功不能得分。评分仍只代表**本地观察任务成功**，不能解释为漏洞发现或确认。

`run_outcome` 区分 `task_passed`、`task_failed` 和 `environment_error`。模型服务不可用、认证失败、进程异常或超时归环境错误，不计入任务解题率分母；正式实验仍保留该次记录。更换模型后应视作不同配置，不能混在同一成功率里。这个脚本没有全局任务请求预算；本任务的实际工具使用由独立评分要求一次 GET，未来多轮自主任务开放前仍须补齐运行级预算和停止条件。

## 2026-10-01 首次复演

在 OpenCode 1.18.29、`deepseek/deepseek-flash` 和相同源码摘要下，两次独立运行均通过本题评分（2/2）：每次模型调用一次 `authorized_web_observe`，靶站收到一次 GET，EV 校验有效，最终回答包含实际状态码。这个数字仅适用于该本机观察题。开发时两种免费模型在工具执行前被供应商拒绝；一次把工作目录放在仓库内部导致 OpenCode 继承主项目配置，被 Scope Guard 拦截。修正后使用仓库外目录，两次成功记录及早期失败记录均保留在各自运行目录。
